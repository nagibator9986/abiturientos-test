# Платформа вступительного тестирования — Caspian College

Веб-платформа для проведения вступительного теста по английскому языку для абитуриентов:
абитуриент вводит ФИО, проходит тест онлайн, результат автоматически проверяется и сохраняется
в базе; приёмная комиссия работает с результатами в защищённой админ-панели с поиском,
фильтрами и выгрузкой в Excel/CSV.

**Стек:** Flask 3 · SQLAlchemy 2 · SQLite (WAL) · Tailwind CSS 3 (собранный, без CDN) · ванильный JS.

---

## Быстрый старт

```bash
cd test-for-abituients
pip install -r requirements.txt      # Flask, Flask-SQLAlchemy
python3 run.py
```

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:8080/ | Тестирование для абитуриентов |
| http://127.0.0.1:8080/admin | Админ-панель приёмной комиссии |

> Порт по умолчанию — 8080 (порт 5000 на macOS занимает служба AirPlay Receiver).
> Если он занят, приложение само возьмёт ближайший свободный и напечатает адрес
> при запуске. Явно порт задаётся переменной `PORT`.

**Доступ в админку:** логин `admin`, пароль `admin123321` (меняется в разделе «Настройки»).

При первом запуске автоматически создаются: база `instance/testing.db`, учётная запись
администратора, настройки по умолчанию и банк вопросов из `data/*.json`.

## Что умеет платформа

### Для абитуриента
- Регистрация: ФИО (обязательно), телефон, e-mail, школа/колледж, выбор варианта.
- Валидация ФИО (минимум фамилия + имя, только буквы/дефис/апостроф, кириллица и латиница,
  включая казахские буквы) и нормализация: `«  иванов  иван »` → `«Иванов Иван»`.
- Прохождение теста: разделы, тексты для чтения, 3–4 варианта ответа, панель навигации по вопросам.
- **Автосохранение каждого ответа на сервере** сразу после клика (fetch + CSRF-токен),
  с повторными попытками при обрыве связи — работа не теряется при закрытии вкладки.
- Таймер с серверным контролем: обратный отсчёт, подсветка последних 5 минут,
  автозавершение по истечении времени (и на стороне браузера, и на сервере).
- Подтверждение отправки с предупреждением о неотвеченных вопросах.
- Страница результата: балл, процент, оценка, уровень CEFR, разбивка по разделам, печать.

### Для приёмной комиссии (`/admin`)
- Вход по паролю (хеш `pbkdf2`), блокировка после 8 неудачных попыток на 5 минут.
- **Дашборд:** всего работ, завершено, средний результат, доля преодолевших порог,
  активность за 14 дней, распределение результатов по диапазонам, статистика по вариантам,
  последние работы, самые сложные вопросы (доля верных ответов).
- **Результаты:** поиск по ФИО, телефону, e-mail, школе и ID попытки —
  регистронезависимый и для кириллицы; фильтры по варианту, статусу, диапазону дат
  и диапазону процентов; сортировка по любому столбцу; пагинация 20/50/100/200.
- **Карточка работы:** данные абитуриента, итог, разбивка по разделам и полный лист ответов
  (ответ абитуриента против эталонного), печать, удаление.
- **Экспорт CSV** (разделитель `;`, UTF-8 BOM — корректно открывается в Excel) с учётом
  текущих фильтров.
- **Банк вопросов:** просмотр вариантов, вопросов и ключей, статистика верных ответов
  по каждому вопросу, включение/отключение варианта, пересчёт всех работ после правки ключа.
- **Настройки:** название заведения, заголовок теста, часовой пояс, длительность,
  проходной балл, показывать ли абитуриенту результат и разбор ответов,
  разрешать ли повторные попытки, смена пароля.

### Правки приёмной комиссии (24.08.2026)

Внесены по документу `Entrance test 2-в.docx` и замечаниям к варианту 1-в:

| Вариант | № | Правка |
|---|---|---|
| 2-в | 3 | ключ подтверждён: **C** «Isn’t going to» |
| 2-в | 6 | добавлено слово: «I went to the shop ________ some **food**.» |
| 2-в | 8 | добавлено слово: «Have you **ever** visited London?» |
| 2-в | 21 | ключ изменён на **C** «Should» (было D «Had») |
| 2-в | 30 | вопрос «she ________ from her job yesterday» убран; вопросы 31–51 перенумерованы в 30–50 |
| 2-в | 30–32, 33–37, 38–40, 41–45 | добавлены описания заданий |
| 1-в | 18 | ключ подтверждён: **D** «So do I» |
| 1-в | 31–35, 41–45, 46–48, 49–50 | добавлены описания заданий |

Описание задания («Choose the appropriate answer», «Read some texts and find the right
answers» и т. п.) хранится в поле `instruction` и показывается над текстом вопроса —
и абитуриенту, и в админ-панели.

**Ключ ответов.** В исходных документах правильные ответы отсутствовали — ключ составлен
и проверен отдельно: каждый вопрос независимо решался тремя экспертными проходами
(грамматический разбор, носительская идиоматика, логика составителя теста), все спорные
позиции дополнительно разбирались отдельно по каждому варианту ответа. Итог: 101 из 101
вопроса подтверждён единогласно.

Формат вопроса:

```json
{
  "n": 7,
  "section": "Grammar & Vocabulary",
  "instruction": "необязательное описание задания",
  "passage": "необязательный текст для чтения",
  "prompt": "When I was a student I ______ to discos every Friday night.",
  "options": {"A": "used to go", "B": "was used to go", "C": "use to went", "D": "used to going"},
  "answer": "A"
}
```

Правка банка: отредактируйте JSON → `flask --app run sync` → при изменении ключа
`flask --app run regrade` или кнопка «Пересчитать результаты» в разделе «Банк вопросов».

**Защита истории.** Вопросы сопоставляются по номеру `n`. Если формулировка вопроса
изменилась, а по нему уже есть ответы, синхронизация такой вопрос пропускает и пишет
предупреждение — иначе ответы сданных работ молча «переехали» бы на другой вопрос.
То же правило действует при удалении вопроса или варианта ответа. Осознанная перезапись —
`flask --app run sync --force` (после неё запустите `regrade`).

Поэтому правьте банк так: меняете ключ или опечатку в тексте — можно в любой момент;
добавляете/удаляете вопросы с перенумерацией — только до начала приёма работ.

## Модель данных

```
Variant 1─* Question 1─* Option
   │                        ▲
   *                        │
Attempt 1─────* Answer ─────┘
```

- `Attempt` хранит ФИО, контакты, статус (`in_progress` / `submitted` / `expired`), время начала,
  дедлайн, время завершения, все счётчики, процент, оценку, уровень CEFR, IP и user-agent.
- `Answer` — по одному ответу на вопрос (`UNIQUE(attempt_id, question_id)`), с зафиксированной
  правильностью; при пересчёте она обновляется по актуальному ключу.
- `Attempt.search_text` — предрассчитанная строка в нижнем регистре (ФИО + телефон + e-mail +
  школа + ID) для регистронезависимого поиска по кириллице (SQLite `lower()` кириллицу не понимает).

## Надёжность сохранения

Требование «чтобы всё чётко сохранялось» закрыто на нескольких уровнях:

1. Каждый ответ уходит на сервер сразу после клика и пишется в SQLite (WAL) отдельной
   транзакцией; в интерфейсе виден индикатор «Сохранено».
2. При обрыве связи ответы копятся в очереди и повторяются с нарастающей паузой;
   ответ, изменённый во время отправки, не теряется.
3. При завершении теста форма дублирует все ответы — сервер сохраняет их ещё раз.
   Даже при полностью отказавшем автосохранении (или отключённом JS) работа не пропадёт.
4. Уникальный индекс `(attempt_id, question_id)` плюс обработка конфликта: параллельные
   запросы из двух вкладок не создают дублей (проверено 32 одновременными запросами).
5. После подсчёта результата опоздавший ответ отклоняется атомарно (`409`), поэтому
   сохранённый балл всегда соответствует листу ответов.
6. Работа с истёкшим временем закрывается сервером и оценивается по сохранённым ответам.

## Безопасность

- `SECRET_KEY` не зашит в код: берётся из окружения, иначе генерируется случайным
  и сохраняется в `instance/secret_key` (права 600). Подделать сессию администратора,
  зная исходный код, невозможно.
- CSRF-токен обязателен для всех POST/PUT/PATCH/DELETE (форма или заголовок `X-CSRF-Token`).
- Пароль администратора хранится хешем (`werkzeug.security`), в коде и БД открытым текстом нет.
  При запуске в продакшене с паролем по умолчанию в лог пишется предупреждение.
- Блокировка входа: 8 неудачных попыток → 5 минут паузы для этого IP. Заголовок
  `X-Forwarded-For` учитывается только при `TRUST_PROXY=1` (иначе блокировку можно обойти),
  таблица попыток ограничена по размеру.
- Отладчик Werkzeug выключен по умолчанию — включается только `FLASK_DEBUG=1`.
- Абитуриент видит только свою попытку (привязка к сессии), чужая — `403`.
- API отклоняет: ответ на вопрос из чужого варианта, несуществующую букву ответа,
  ответ после завершения работы (`409`), запрос без CSRF (`400`).
- Ключ ответов не отдаётся на страницу теста; разбор ответов абитуриенту показывается,
  только если это явно включено в настройках. Страница теста отдаётся с `no-store`,
  поэтому кнопка «назад» не возвращает сданную работу.
- Экспорт CSV экранирует ячейки, начинающиеся с `= + - @` (защита от формул в Excel).
- `SESSION_COOKIE_HTTPONLY`, `SameSite=Lax`, ограничение размера запроса 1 МБ.

## Запуск в продакшене

```bash
pip install gunicorn
python3 -m flask --app run init-db                  # инициализация до старта воркеров
SECRET_KEY='случайная-строка' FLASK_ENV=production \
  gunicorn -w 4 -b 0.0.0.0:8000 'run:app'
```
Рекомендации: задайте свой `SECRET_KEY`, смените пароль администратора
(`flask --app run set-admin-password '...'`), при работе по HTTPS установите `FORCE_HTTPS=1`,
а за обратным прокси — `TRUST_PROXY=1`. Инициализация БД защищена файловой блокировкой,
поэтому запуск нескольких воркеров безопасен.

## Часовой пояс

В базе всё хранится в UTC, а показывается и фильтруется в поясе из настроек
(по умолчанию `Asia/Almaty`, UTC+5). Смена пояса в админ-панели сразу меняет и время
в таблицах, и границы фильтров «Дата с / по», и суточную статистику дашборда.
